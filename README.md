## Featured project · TransoraPlus

**How can someone follow a signed coding lesson while working through the code?** TransoraPlus is a visual coding studio for Deaf and hard-of-hearing learners. It puts an instructor’s signed recording beside the editor so a learner can pause an explanation, try an idea and return to the same lesson. The prototype includes ten introductory exercises.

| Inside the studio | How it works |
| --- | --- |
| Signed lessons | An instructor’s local recording can be paired with WebVTT captions in the companion panel. |
| Hands-on coding | HTML and JavaScript run in the browser. Python exercises use Pyodide so the learner can experiment in the editor. |
| Progress across visits | A Python backend and SQLite database connect an account to its drafts, completed exercises and community replies. |
| Help during an exercise | Authored hints work out of the box. An optional AI guide uses the current question, lesson and relevant editor text to answer in context. |

**Try the project:** Open a lesson, save an unfinished solution, then return to it. That short walkthrough shows how the editor, account and persistence layer fit together. [Explore TransoraPlus and its local setup guide →](https://github.com/Ayanjaved1/TransoraPlus#readme)

## A data question I’d like to explore

Which exercises do learners return to before finishing? I’d start by defining a return visit, then compare the share of learners who revisit each exercise. A high revisit rate could indicate a difficult instruction or a lesson people find worth practicing. I’d want learner feedback before deciding which explanation fits.

That combination of analysis and product work is what I’m looking for in my next role: a concrete question, data I can examine and a decision the answer can inform.
